# Alder review, 2026-11-18

Scope: the working tree on `fix/p0-release` (with uncommitted changes) and the installed 1.3.1 on the test TV.
Method: seven read-only reviewers by area, one TV walk-through with no playback. Every finding below was re-read
against the source. Findings that did not survive that check are listed at the end.

Unit tests: 132 pass, 0 fail (`testDebugUnitTest`).
TV: cold start to Home 0.94–1.14 s (two runs, TV awake). PSS 108 MB. 1.8% janky frames since process start.
No crash, ANR or StrictMode line from Alder in logcat.

## Fix first (data loss or crash)

1. **Add-on list can be wiped.** `AddonsActivity.kt:75,125,224`. The "Add by URL" row is drawn while `addons` is
   still `emptyList()` (during load, or after load failed). `install()` then calls `save(addons + it)`, and
   `Stremio.setAddons` replaces the account's whole list with that one add-on. Same file, `:194-233`: `addons` is
   updated only after a save returns, so two quick edits both start from the old list and the second undoes the
   first (a removed add-on comes back, a new one disappears). Fix: do not draw or allow Add until the list loaded;
   ignore edits while a save is in flight.
2. **Details crashes on any key when the title failed to load.** `DetailsActivity.kt:1648`
   `it === playButton` reads a `lateinit` that `showHero(null)` never sets. Offline with no saved details, the retry
   card has focus, and Back (or any key) throws `UninitializedPropertyAccessException`. Fix: `::playButton.isInitialized`
   as the line already does for `buttonRow`.
3. **Title page goes blank when fresh details land while the episode guide is open.** `DetailsActivity.kt:181-182`.
   `show()` calls `buildGuide()`, which sets `guideOpen = false` and makes the new guide `GONE`, while `showGuide()`
   had set the hero `INVISIBLE`. Nothing is on screen and nothing has focus. Fix: in `show()`, keep the guide open
   (rebuild then `showGuide()`) or restore the hero.
4. **Mid-film network blips switch the source.** `PlayerActivity.kt:489,507`. `retries` resets only before the
   first frame. The third blip in a long film skips the retry and calls `next()`, which changes source or opens the
   source list mid-film. Fix: reset `retries` once playback recovers (e.g. on `STATE_READY` after a retry).
5. **Picking a source from Change stream keeps the old source's state.** `PlayerActivity.kt:2068`
   `sourcesClosed` does not reset `asHls`, `audioPicked`, `subsPicked`, `failedAudio`, `stalls`, `retries`, which
   `next()` resets at `:944-949`. After an HLS source, a plain file is forced to `APPLICATION_M3U8` and fails;
   audio and subtitle auto-pick never run for the new source. Fix: one `resetSourceState()` called from both.

## Fix soon

6. **Intro skip from MKV chapters never works past the first 64 KB.** `MkvChapters.kt:191-193`
   `findSegmentDataStart` calls `reader.skip(0)` on the EBML header, so it walks into the header's children and then
   into a data byte, and `readId` returns null. The second range request is unreachable. Fix: `reader.skip(size)`.
   No test covers this function.
7. **Picking an add-on subtitle while paused starts playback.** `PlayerActivity.kt:2553` `load(position())` uses
   `play = true` by default. Fix: `load(position(), play = player.playWhenReady)`.
8. **Saves fail silently.** `PlayerActivity.kt:1285`, `DetailsActivity.kt:539,774`: `background({ saveLibrary }) {}`.
   Offline, My List and watched ticks look saved and are lost on the next refresh; the last player push is lost.
   Saves also run unordered on a 6-thread pool, so two quick ticks can land oldest-last.
9. **`Stremio.saving` is never cleared after a successful save.** `Stremio.kt:76,98`. For the rest of the process,
   the local copy wins whenever its `_mtime` string is larger. A TV clock that runs ahead hides progress saved on
   the phone and then writes over it. Fix: remove the entry on success.
10. **One bad add-on manifest empties Home.** `Addon.kt:17,65`, `Stremio.kt:43`: `.map(::Addon)` with
    `getJSONObject`/`getString` and no per-item guard. One malformed manifest fails the whole list, including the
    saved one offline. Same for one meta without `id` in a catalog row (`Addon.kt:226`). Fix: `mapNotNull { runCatching { Addon(it) }.getOrNull() }`.
11. **Main-thread disk (and possible network) work per Continue Watching item.** `MainActivity.kt:1369,2514`:
    `Stremio.savedAddons(key)` reads and parses the add-on file for each finished episode on every `show()`; if it
    is null, `Stremio.addons(key)` runs on main and the `NetworkOnMainThreadException` is swallowed. Misses are
    not cached, so they repeat.
12. **Clear storage bypasses profile PINs.** `SettingsActivity.kt:599-604`. Settings opens with no PIN, and Clear
    storage wipes every profile. Removing one profile needs its PIN. Ask for a PIN (any locked profile's) first.

## Lower

- Subtitle downloads have no size cap and a per-read timeout only (`Http.kt:92`, `SubtitleFiles.kt:37,40`): a
  big or zip/gzip-bomb subtitle can OOM the TV. Subtitle cache write is not atomic, keyed by `hashCode()`, and never
  evicted (`SubtitleFiles.kt:24-27`).
- Updater takes `browser_download_url` without checking https or host (`Updates.kt:32,103`); the APK also goes
  into the 250 MB HTTP cache. PackageInstaller's same-signature rule is the only guard.
- `Http.keep` uses a fixed `.tmp` name (`Http.kt:52`); two threads saving the same request interleave bytes.
- Proxy headers from add-ons are re-sent to any redirect host (`MkvChapters.kt:273-279`).
- Stopping in the subtitle wait leaves `stopWaiting` posted (`PlayerActivity.kt:647`); it later calls `begin()` on
  the released player and starts a tick loop that holds the Activity.
- Forward seeks under 20 s count as watched time (`PlayerActivity.kt:1047`).
- Sign-in: Back during the user-id lookup still creates the profile and opens Home (`ProfilesActivity.kt:647-679`).
- `Page.of` mutates a plain map from the pool in `warmPages` (`MainActivity.kt:213,1866`); a lost write gives two
  tabs for one type.
- Search's top bar is its own hard-coded list (`SearchActivity.kt:281`): no Discover or Live, while Home shows both.

## Project health

- **No CI for the app.** `.github/workflows/` has only `pages.yml`. Add a PR workflow running
  `testDebugUnitTest` and `lintDebug`.
- **No tests for the money paths:** `Library.record/stopped/resumeAt/markWatched`, `Stremio.saveLibrary/newest`,
  `Profiles`. These write the user's real account.
- **God classes:** `PlayerActivity.kt` 3,202 lines, `MainActivity.kt` 2,726, `DetailsActivity.kt` 1,683. Failover,
  track choice and progress sync in the player are pure enough to move out and test.
- **CRLF churn:** `MainActivity.kt` is CRLF in the working tree, LF in git. Committing it rewrites 5,260 lines for a
  256-line change. Add `.gitattributes` (`* text=auto eol=lf`) or convert before committing.
- Release signing falls back to the debug key when `keystore.properties` is missing (`app/build.gradle.kts:47`).
  Fail the release build instead.
- TMDB key is in source (`Tmdb.kt:10`). Fine for a public read key; know it is public.
- Known issues 43 and 44 (Android 7 crash fix unreleased, no mapping files kept) still stand.
